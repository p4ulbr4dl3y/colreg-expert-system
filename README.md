# Экспертная система предупреждения столкновений судов

Продуктовое решение для оценки навигационных рисков и выработки рекомендаций по расхождению судов в соответствии с Международными правилами предупреждения столкновений судов в море (МППСС-72).

Система анализирует координаты и параметры движения собственного судна и окружающих судов-целей, оценивает риски столкновения, строит карту опасных секторов курса и предлагает безопасные траектории маневрирования с учетом маневренных характеристик судна.

## Основные возможности

Система предоставляет следующий набор функций:
- многоцелевой анализ обстановки: одновременный расчет рисков для произвольного количества окружающих целей;
- расчет геометрических параметров сближения: вычисление дистанции кратчайшего сближения (CPA) и времени до него (TCPA);
- определение взаимного статуса и приоритета судов: классификация ситуаций по секторам обгона, встречного сближения и пересечения курсов с учетом приоритета типов судов согласно МППСС-72;
- динамическая адаптация зоны безопасности: масштабирование защитного радиуса при обнаружении целей в критической близости;
- учет ограничений авторулевого: автоматическая блокировка поворотов на левый борт в ситуациях встречного сближения и пересечения курсов согласно правилам 14, 15 и 17;
- проверка физических ограничений маневрирования: проверка возможности завершения маневра до наступления момента кратчайшего сближения на основе радиуса циркуляции и скорости судна;
- поддержка работы в условиях ограниченной видимости: применение логики правила 19 с автоматической подстройкой ограничений на развороты в зависимости от положения целей относительно траверза.

## Архитектура проекта

Кодовая база разделена на следующие модули:
- `src/models.py`: содержит структуры данных для судов, окружающей среды, индивидуальных и общих решений, а также структуры трассировки вывода (`ProofStep`, `InferenceTrace`);
- `src/geometry.py`: реализует векторную математику для расчета траекторий сближения, секторов опасных курсов и параметров поворота;
- `src/geometry_facts.py`: преобразует `Vessel` и `Environment` в ground-факты для формального движка;
- `src/formal/`: пакет формального движка экспертной системы (см. раздел «Формальный движок»);
- `src/inference.py`: точка входа — класс `COLREGInferenceEngine` со сигнатурой `.evaluate(own, targets, env, wind_direction)`;
- `src/engine.py`: тонкий re-export `COLREGInferenceEngine` для обратной совместимости со старым импортом;
- `src/rules.py`: помечен как legacy, сохранён для обратной совместимости со старыми тестами;
- `main.py`: предоставляет консольный интерфейс для ручного тестирования и запуска демонстрационных сценариев;
- `scripts/mqtt_node.py`: реализует асинхронный сетевой узел, принимающий навигационные данные и публикующий результаты через протокол MQTT (в payload добавлены поля `fired_rules` и `trace`);
- `scripts/mqtt_simulate.py`: отправляет тестовый навигационный запрос в брокер сообщений для верификации работы сетевого узла.

## Формальный движок

Экспертная система реализована как декларативная база знаний (правила МППСС-72) + самописный движок прямой цепочки на чистом Python (~300 строк без зависимостей).

### Архитектура

```
+--------------------------+
| Vessel, Environment      |  входные структуры
+--------------------------+
            |
            v
+--------------------------+
| geometry_facts.py        |  численная геометрия (CPA, TCPA, пеленги)
+--------------------------+  --> ground-факты Predicate
            |
            v
+--------------------------+
| src/formal/              |  формальный движок
|   substitution.py        |  Var, Const, унификация
|   world.py               |  FactBase с индексацией
|   builtins.py            |  in_range, gt, eq, and_, or_
|   engine.py              |  ForwardChainer + ProofStep
|   kb/                    |  40 правил МППСС-72 (rule_12, 13, 14, 15,
|                          |      17, 18, 19, 34, 35, helpers)
+--------------------------+
            |
            v
+--------------------------+
| Decision                 |  collision_risk, own_role, recommended_action,
+--------------------------+  recommended_heading, forbidden_sectors,
            |               |  target_decisions, explanation, trace
            v
+--------------------------+
| MQTT / Web / Console     |  три интерфейса
+--------------------------+
```

### Представление правил

Каждое правило МППСС-72 — `dataclass Rule`:

```python
Rule(
    id="rule_14_head_on",
    citation="МППСС-72 правило 14 (a)",
    description="встречное сближение: оба суда изменяют курс вправо",
    tag="rule_14",
    precedence=100,  # для разрешения конфликтов между правилами
    premises=(
        Predicate("risk_exists", (Var("?own"), Var("?tgt"))),
        Predicate("equal_priority", (Var("?own"), Var("?tgt"))),
        Predicate("reciprocal_courses", (Var("?own"), Var("?tgt"))),
        Predicate("both_see_headon", (Var("?own"), Var("?tgt"))),
    ),
    conclusions=(
        Predicate("encounter_type", (Var("?own"), Var("?tgt"), "head_on")),
        Predicate("own_role", (Var("?own"), Var("?tgt"), "BOTH_GIVE_WAY")),
        Predicate("recommended_action", (Var("?own"), Var("?tgt"), "ALTER_COURSE_STARBOARD")),
    ),
)
```

Добавление нового правила = одна запись в соответствующем файле `src/formal/kb/`. Никакого императивного кода.

### Разрешение конфликтов

Когда несколько правил выводят разные значения одного предиката (например, разные `encounter_type` для одной и той же пары судов), побеждает правило с наибольшим `precedence`. Иерархия:

- `200` — правило 12 (парусные суда, наиболее специфично)
- `110` — правило 17 (маневр крайнего момента, override)
- `100` — правило 14 (встречное сближение)
- `90` — правило 19 впереди траверза
- `85` — правило 19 (остальные)
- `80` — правило 13 (обгон)
- `60` — правило 15 (пересечение)
- `50` — правило 18 (приоритет типов)

### Трассировка

Каждое срабатывание правила записывается в `ProofStep` с полным контекстом (посылки, заключения, подстановка переменных). Полная трассировка доступна в `Decision.trace` и `Decision.fired_rules`, а также публикуется в MQTT payload.

### Преимущества по сравнению со старым движком

- знания отделены от вывода: правка правила = правка одной записи в KB;
- автоматическая проверка: каждая `Var` в заключении обязана быть связана в посылках (`tests/test_kb_integrity.py`);
- полная трассировка для аудита решений;
- разрешение конфликтов через `precedence` — декларативно, без if-else в Python;
- нет внешних зависимостей для движка вывода (только стандартная библиотека).

## Установка и требования

Для работы требуется установленный интерпретатор Python версии 3.12 или выше. Рекомендуется использовать менеджер пакетов `uv`.

Шаги по установке:
1. Клонируйте репозиторий:
   ```bash
   git clone git@github.com:p4ulbr4dl3y/expert-system.git
   cd expert-system
   ```
2. Создайте виртуальное окружение и установите зависимости:
   ```bash
   uv sync
   ```

## Запуск демонстрационного интерфейса

Запуск интерактивного консольного меню выполняется командой:
```bash
uv run python main.py
```
В меню доступны следующие действия:
- 1: запуск стандартных навигационных сценариев расхождения (включая многоцелевой конфликт и проверку инерционных ограничений);
- 2: ввод параметров собственного судна и целей вручную для проведения расчетов;
- 3: выход из программы.

## Работа по протоколу MQTT

Экспертный узел может быть интегрирован в судовую сеть. Он обменивается сообщениями по следующим топикам:
- `colreg/expert/command`: топик для входящих команд с параметрами судов;
- `colreg/expert/result`: топик для публикации выработанных решений.

Для проверки работы выполните следующие шаги:
1. Запустите MQTT-брокер на локальном хосте (порт 1883).
2. Запустите сетевой узел экспертной системы:
   ```bash
   uv run scripts/mqtt_node.py
   ```
3. В отдельном терминале отправьте тестовый запрос через симулятор:
   ```bash
   uv run scripts/mqtt_simulate.py
   ```

## Тестирование

Запуск набора автоматических тестов, проверяющих расхождение в различных ситуациях:
```bash
uv run python -m unittest discover tests
```
